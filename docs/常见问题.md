# 常见问题

## 登录显示「网络错误，请稍后重试」

页面文案来自 `login.html` 的 `catch`：请求失败或响应不是 JSON，**不是**「账号密码错误」。

常见原因：

1. **后端未启动**：`docker ps` 中无 `ams-backend`，或 Nginx 反代 502。
2. **用 `file://` 打开了本地 HTML**：地址栏应为 `http://127.0.0.1/...`。
3. **Navicat 等占用了 `data/assets.db`**：锁库导致接口异常。先断开工具，必要时 `docker restart ams-backend`。
4. 只起了 Nginx、后端挂掉：页面能开，一点登录就网络错误。

自检：

```bash
docker ps
curl -s http://127.0.0.1:8088/api/auth/check
curl -s http://127.0.0.1/api/auth/check
```

浏览器 F12 → Network 查看 `POST /api/auth/login` 状态码。密码错误时应看到业务 JSON 错误文案，而不是「网络错误」。

## 用户表里 password 像乱码，能当密码登录吗？

不能。那是 **PBKDF2 哈希**（通常以 `pbkdf2$` 开头），登录框必须填明文口令。演示账号明文见 `演示账号.txt`；超管口令不由演示种子重置，见该文件「超管」一节。

## 数据文件在哪？用什么软件看？

正式库：`data/assets.db`（相对本项目根目录）。Docker 将该目录挂进容器，宿主机改文件即改运行库。

可用 DB Browser for SQLite、Navicat（SQLite）、或 `sqlite3` CLI。**服务运行时请避免长时间写锁**；要改库先停 `ams-backend`。

pytest 使用临时库，不会写入正式 `assets.db`。

## 超管密码在哪看？

按优先级：

1. **`data/INITIAL_ADMIN_PASSWORD.txt`**（交付包预置，或空库首次建超管时自动生成）  
2. **`演示账号.txt`** 中「超管」一节（交付包默认口令）  
3. `deploy.sh` 部署结束时的终端输出  
4. 若以上都没有：`docker logs ams-backend` 中含「初始密码」的一行  

登录后请立即改密；生产环境改密后可删除 `INITIAL_ADMIN_PASSWORD.txt`。仍登不进时可用 `manage.sh set-superadmin` 重置。

可在用户管理中由超管重置他人密码；自己的口令用「修改密码」接口/页面。

## 财务 / 操作员菜单少了，是不是接口也拦了？

否。当前仅裁剪管理端导航与默认落地页；后端管理接口仍按「是否管理角色」大桶校验。详见 `更新说明.md` §1。

## 管理端改了 main.html 但浏览器没变化？

可能原因：① 看的是 `index.html` / 根路径 `/`（Nginx 默认 index）；② 打开了另一套部署目录的前端挂载；③ 需强刷。两文件应保持一致（更新说明 §9）。

## 「我的资产」为空？

新资产申请通过后须在「待发放」选在库资产完成发放，关联人写上申请人才会出现在 `GET /api/my/assets`。匹配按关联人**姓名**精确相等。

## 飞书免登怎么进？

1. 在 `.env` / compose 配置 `LARK_APP_ID`、`LARK_APP_SECRET`、`LARK_REDIRECT_URI`（回调须与开放平台一致）。
2. 飞书开放平台为应用开通「获取用户 user ID」（`contact:user.employee_id:readonly`），便于 `user_info` 返回 `user_id`。
3. 在「用户管理」为员工填写 Lark User ID（或走待绑定审核）。不按邮箱匹配：官方不建议把未经验证的邮箱当登录凭证。
4. 用**飞书客户端**打开站点正式域名：会自动授权 → `lark-code-login` 按 `user_id`/`open_id`/`union_id` 换 token；管理角色进 `/main.html`，普通用户进 `/my.html`。

浏览器非飞书环境、以及本机 `127.0.0.1` 等局域网调试地址：仍用账号密码，不会强制跳飞书。`POST /api/auth/lark-login` 已停用（410），请勿依赖。

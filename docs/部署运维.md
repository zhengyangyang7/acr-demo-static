# 部署与运维

日常启停、访问、备份与换库。接口行为见根目录 `更新说明.md`。

## 1. 组件与端口

| 组件 | 容器名 | 宿主机端口 | 作用 |
| --- | --- | --- | --- |
| 后端 Flask/gunicorn | `ams-backend` | 8088 | API；也可直接提供静态页 |
| Nginx | `ams-nginx` | 80（及可选 443） | 静态前端；`/api/` 反代到 backend |

Compose 将 `./data` 挂到容器 `/app/data`（库文件与 uploads），将 `./frontend` 挂到 Nginx html 目录。

环境变量要点：`DATA_DIR=/app/data`；飞书免登需配置 `LARK_APP_ID`、`LARK_APP_SECRET`、`LARK_REDIRECT_URI`（须与飞书开放平台回调一致；compose 已从 `.env` 注入）。未配置时飞书内授权会失败并跳登录页提示；浏览器仍可用密码登录。

## 2. 常用命令

在含 `docker-compose.yml` 的目录：

```bash
docker compose up -d --build   # 构建并启动
docker compose ps              # 状态
docker logs -f ams-backend     # 后端日志
docker restart ams-backend     # 仅重启后端
```

或使用 `manage.sh`（按**容器名**操作，不依赖 compose 项目名）：

```bash
bash manage.sh status
bash manage.sh logs 100
bash manage.sh restart
bash manage.sh backup-db
bash manage.sh deploy          # 调用 deploy.sh，保留现有 data/assets.db
```

Linux 首次/全量部署：

```bash
sudo bash deploy.sh
```

## 3. 访问地址

| 场景 | URL |
| --- | --- |
| 本机经 Nginx | `http://127.0.0.1/login.html` |
| 本机直连后端 | `http://127.0.0.1:8088/login.html` |
| 局域网 | `http://<主机局域网IP>/login.html` |

登录后：管理角色进 `/main.html`，普通用户进 `/my.html`。不要用资源管理器双击打开 `login.html`（`file://` 下 `/api` 无服务）。

健康探测示例：

```bash
curl -s http://127.0.0.1:8088/api/auth/check
curl -s http://127.0.0.1/api/auth/check
```

## 4. 数据与备份

| 路径 | 说明 |
| --- | --- |
| `data/assets.db` | 正式 SQLite 库 |
| `data/assets-initial.seed` | 空环境初始化种子（deploy 在无库时拷贝） |
| `data/INITIAL_ADMIN_PASSWORD.txt` | 超管初始明文密码（交付包预置或首次建库写入；deploy 结束会打印） |
| `data/assets.db.bak-*` | `manage.sh backup-db` 等产生的备份 |
| `data/uploads/` | 上传附件（发票/照片等） |

备份：

```bash
bash manage.sh backup-db
```

换库验证（会先停后端、备份旧库、再启动）：

```bash
bash manage.sh swap-db path/to/another.db
```

恢复：

```bash
bash manage.sh restore-db data/assets.db.bak-YYYYMMDD-HHMMSS
```

注意：服务运行时用 Navicat 等工具**长时间占用或写入**同一 `assets.db`，可能导致后端锁库、登录表现为「网络错误」。改库前先 `docker stop ams-backend`，改完再 `docker start ams-backend`。备份脚本对 WAL 下的裸 `cp` 并非完美在线快照；重要备份前宜停写或停后端。

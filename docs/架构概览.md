# 架构概览

帮助定位「改哪里、数据在哪、权限边界到哪」。已交付细则仍以 `更新说明.md` 为准。

## 1. 请求路径

```text
浏览器
  → Nginx :80（静态 frontend/，/api/ 反代）
  → ams-backend :8088（gunicorn → wsgi:app → app.py）
  → SQLite data/assets.db
```

也可直连 `:8088`（后端同时可提供部分静态路由）。上传文件落在 `data/uploads/`，Nginx 另挂载为 `/uploads/`。

## 2. 目录职责

| 路径 | 职责 |
| --- | --- |
| `backend/app.py` | 几乎全部 HTTP API 与业务（单体，未拆 Blueprint） |
| `backend/database.py` | 建表、迁移补列、`get_conn`、密码哈希 |
| `backend/wsgi.py` | gunicorn 入口 |
| `backend/tests/` | pytest；临时库，不碰正式 `data/assets.db` |
| `backend/_seed_demo_charts.py` | 演示数据 |
| `frontend/main.html` / `index.html` | 管理端 SPA（需同步维护，内容应一致） |
| `frontend/my.html` / `profile.html` | 个人门户 |
| `frontend/ams-role.js` | 管理角色白名单、菜单可见性、落地页 |
| `frontend/auth.js` / `auth-guard.js` | Token 与页面守卫 |
| `frontend/*.html`（stock/orders/…） | 独立业务页 |
| `nginx/` | 反代与缓存头 |
| `data/` | 库与上传（运行时，勿当源码提交敏感口令） |

## 3. 认证与角色（边界）

- 登录：`POST /api/auth/login`（姓名或邮箱 + 密码）；飞书内走 OAuth code → `POST /api/auth/lark-code-login`。密码存 PBKDF2（`pbkdf2$...`），非明文。
- Token：入库会话；前端主路径用 `localStorage`（`ams_token`）。
- 全局钩子：未登录拦 API；管理接口要求角色属于 `ADMIN_ROLES`（超管 / 管理员 / 普通管理员 / 操作员 / 财务）。匿名白名单含 `lark-signature` / `lark-code-login`；不安全的 `lark-login` 返回 410。
- **部门菜单裁剪只在前端**（`ams-role.js`）：财务等隐藏部分侧栏；后端未按财务/操作员再细分接口。独立页守卫目前主要拦「非管理角色」，不套菜单白名单。详见更新说明 §1 与 §9。

## 4. 核心业务对象（概念）

| 概念 | 典型表 / 字段 | 说明 |
| --- | --- | --- |
| 员工 | `employees` | 角色、密码哈希、部门 |
| 资产 | `assets` | 状态：在库/在用/维修中/已报废等；关联人多为姓名文本 |
| 申请 | `asset_applications` | 审批状态；`fulfilled` 发放标记；`po_id` 可选关联订单 |
| 采购订单 | `purchase_orders` 等 | 到货、发票、入库审批 |
| 出入库 / 维修 / 盘点 | `stock_logs`、`repair_logs`、盘点相关表 | 生命周期动作 |

主路径（简化）：申请 → 审批 →（可选）生成/维护采购订单 → 入库在库 → 待发放出库 → 在用 → 归还/报修/盘点。

## 5. 已知工程约束

- 存储为 SQLite；gunicorn 多 worker 写同一库有并发上限。
- `main.html` 与 `index.html` 双入口需人工同步。
- 飞书免登依赖 `LARK_*` 环境变量与员工 `lark_user_id`（或 open_id/union_id）绑定；本机调试地址不强制跳飞书。
- 产品地图 C/D：行政待办带、财务汇总页、月度折旧核对等未做。

演进若动库或权限，优先对齐「服务端 RBAC ↔ 菜单矩阵」与测试，再考虑拆分 `app.py` 或换库。
